核心差别不在检索精度，而在知识是否沉淀。传统 RAG 在查询时才把文档切块、算相似度、临时拼进上下文，答案用完即弃，下一次提问从零开始；而 LLM wiki 把这一步提前到「编译期」——每份素材进来时，模型已经把它的结论写进 实体页 与 概念页，并补上了指向相关页面的 [[反向链接]]。

因此它不需要向量库，靠的是两样东西：一是页面之间的显式结构，模型的导航依据是由LLM 自动维护的 index.md 和每页顶部的摘要，而不是语义近邻；二是百页量级的上下文足够装下——个人知识库通常只在几十到几百页，全文放进上下文的成本远低于维护一套 embedding 流水线。

由此还可以推出一个原料里没有的结论：它的瓶颈是「写」而不是「读」。wiki 的质量取决于 摄入级联更新 的彻底程度，一旦某页没被新素材回溯更新，错误会沿着链接扩散。这解释了为什么原方案必须配 体检 lint 那条动作。
