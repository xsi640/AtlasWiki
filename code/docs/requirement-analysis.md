## 1. 项目概述

一个跑在本机、带 Web 界面的**个人知识库产品**。底层采用 Karpathy 的 LLM Wiki 模式：**不使用向量数据库**，由 LLM 把原始素材「编译」成一组互相 `[[链接]]` 的 markdown 页面，并持续增量维护。

核心差异点：传统 RAG 在查询时临时检索拼接，每次从零开始；本项目在**编译期**就把知识写进页面并建立连接，让知识随时间复利。

一句话定位：**给个人开发者的本地 LLM 知识编译器，带一个看得见界面。**

## 2. 目标用户

| 项 | 内容 |
|---|---|
| 主要使用者 | 项目提出者本人（个人开发者） |
| 使用场景 | 本机 `localhost` 运行，浏览器访问；日常沉淀网页文章、PDF/论文、随手笔记等全领域素材 |
| 前提条件 | 拥有云端 LLM API key；能接受手动命令行启动；愿意承担 LLM 调用成本 |
| 非目标用户 | 团队成员、需要账号/权限管理的多人场景（V1 明确排除） |

---

## 3. 要解决的问题

1. **工具的记忆是临时的**：现有 AI 知识工具（ChatGPT 上传、NotebookLM、各类 RAG）是无状态的，同一批资料每问一次都要重新理解一遍，读得越多、沉淀越少。
2. **整理的苦活没人干**：归档、摘要、交叉引用、更新旧结论、发现新矛盾——这些维护成本让个人知识库普遍在第三个月烂尾。
3. **知识被锁在别人的服务里**：SaaS 知识工具一旦停服或改价，数据难以完整带走；即使工具消失，也应该能拿走全部内容。
4. **整理出来的东西看不见**：纯文件夹方案（Obsidian + 手工）没有界面，知识网络的形状不可见；这是本项目存在的唯一理由。

## 4. 需求目标

| 编号 | 目标 | 用户能获得什么 |
|---|---|---|
| G-1 | 素材进得来、改得了、删得掉 | 网页文章、PDF/论文、随手笔记三类素材可导入成为知识源；**用户本人可编辑与删除素材**，其中手写笔记可编辑正文，其余素材可编辑标题/标签/备注等元数据（正文为外部来源，不可改） |
| G-2 | 知识自动生长 | 每加入一份素材，LLM 自动生成摘要页、新建概念/实体页、更新受影响页面与索引，并标记新旧矛盾 |
| G-3 | 看得见网络 | 在 Web 界面阅读页面、跳转 `[[链接]]`、查看反向链接与全局图谱 |
| G-4 | 能问出新东西 | 对着 wiki 提问，答案跨页面综合并附引用；有价值答案可回填成新页面 |
| G-5 | 能自愈 | 定期体检，发现矛盾、孤儿页、缺失交叉引用，并给出补全建议 |
| G-6 | 过程可信 | 每次 LLM 改动了哪些文件、为什么改，都可查看、可 diff、可依托 git 退回 |
| G-7 | 不被锁定 | 知识以纯 markdown 文件存在，工具不在了文件还能用 |
| G-8 | 自动归档 | 素材入库后由 LLM 自动判断所属分区，无需手工分类维护 |

## 5. 模块边界说明

> 注：下表 `MOD-0X` 为需求分析阶段的**临时代号**，仅用于本次讨论；阶段 3A（技术架构）会将这些模块名称**原样复用**并正式编号为 `MODULE-###`，不得在后续阶段重新命名。

### 模块清单

| 模块代号 | 模块 | 职责 | 不做什么 |
|---|---|---|---|
| MOD-01 | 素材接入 | 三类素材的导入、解析、去重、元数据存储于 `raw/`；支持用户本人编辑（手写笔记可改正文，其余改元数据）与软删除；修改后触发重编译 | 不做内容理解、不写 wiki 页面、不做视频解析与仓库克隆；LLM 不写 `raw/` |
| MOD-02 | 编译引擎 | 执行 ingest：读索引与相关页 → 生成/更新摘要页、概念页、实体页 → 建立互链 → 增量判断所属分区 → 更新索引与日志 → 标记矛盾 | 不直接持有文件读写细节，不负责 UI |
| MOD-03 | Wiki 存储与链接 | md 文件读写、frontmatter 规范（含分区字段）、`[[链接]]` 解析、反向链接计算 | 不做可视化、不自行判断内容归属 |
| MOD-04 | 浏览与图谱 | 页面渲染、跳转、反向链接面板、全局图谱可视化、人工编辑页面 | 不负责自动生成或修改页面内容（除用户主动编辑） |
| MOD-05 | 问答 | 候选页选取 → LLM 跨页综合 → 带引用作答 → 答案回填为新页面 | 不建立独立检索 index（复用 MOD-03 索引） |
| MOD-06 | 体检与维护 | 扫描矛盾、孤儿页、缺失索引、术语不一致、失效链接，产出建议清单 | 不擅自重写用户手改过的页面，不自动覆盖 |
| MOD-07 | 知识规范（Schema） | 页面类型定义、命名规范、frontmatter 字段、三种操作（ingest/query/lint）的行为约束提示词 | 不承载业务运行时数据 |
| MOD-08 | 变更记录与审计 | 每次操作的 log 记录、页面级 diff 展示、变更原因说明、自动 git commit | V1 不做回滚 UI（依托 git 命令行） |
| MOD-09 | 设置与模型接入 | 模型 provider / 模型名 / API key 的配置、成本看板 | 不做多租户、不做账号权限 |

### 边界规则

1. **`raw/` 对人开放、对程序收敛**：**只有用户本人**可以编辑或删除素材；LLM 和任何模块都不得写入 `raw/`。素材被修改后不会自动同步，需要显式触发重编译才会反映到 wiki。
2. **`wiki/` 主要由 LLM 写、人可读可改**：MOD-04 提供人工编辑，编辑过的页面必须打 `human_edited` 标记，MOD-06 体检时**不得自动覆盖**，只能提出建议。
3. **索引属于 MOD-03**：MOD-02 编译、MOD-05 问答消费同一份 `index.md`，不各建一套。
4. **链接解析与绘制分离**：MOD-03 负责「谁链接了谁」（数据），MOD-04 负责画出来（视图）。
5. **问答产物与编译产物同级**：答案回填页也是 wiki 页面，用 frontmatter 的 `source_type` 区分为 `query-generated`，避免与 `compiled` 页面混淆。
6. **分区归属由 MOD-02 判断、MOD-03 存储、MOD-04 展示**：任何模块都不得在未记入 MOD-08 日志的情况下改动页面的分区字段。
7. **分区调整必须是增量的**：每次 ingest 只对本次受影响的页面重新判断归属，不做全库重算，避免分类整体漂移。
8. **删除走软删除**：素材或页面删除后不级联硬删除，其派生页面与入链标记为失效，由 MOD-06 列出待处理清单。

## 6. 成功标准

**SC-1（主标准 · 用户选定）：能对着它问出新东西**

> 同一主题投入不少于 10 篇素材并完成编译后，提出 3 个需要跨素材综合的问题，系统回答需同时满足：
> a. 每条回答至少引用 2 个 wiki 页面，且引用可点击跳转；
> b. 至少 1 个问题能得到「在任何单一原文中都未直接出现」的关系或结论（由本人人工判定成立）。

**SC-2（可用性门槛）**

> 一份新素材从导入到在界面中看到编译结果 ≤ 10 分钟，全过程无需手工干预。

**SC-3（知识网络质量门槛）**

> 10 篇素材编译后，页面平均对外链接数 ≥ 3，孤儿页占比 ≤ 20%。

## 7. 范围与边界

### 必做（V1）

- 单机本地运行，浏览器访问，**无账号、无权限、无多人**
- 文件优先存储：`raw/` + `wiki/` 两套 markdown 文件夹，由 git 自动版本化
- **四个核心动作全部交付**：浏览与图谱、Ingest、Query、Lint
- **素材源三类**：网页文章、PDF/论文、随手写的笔记
- LLM 自动判断页面所属分区（增量式），全过程留痕可回滚
- 云端 LLM API key 驱动，模型可配置切换
- **体检自动触发（轻量）**：应用启动时一次 + 闲置时一次，导航栏常驻「N 个待处理」提醒。**不引入独立的定时调度器**（见「暂不做」）

### 实现顺序与验收节奏约束

四个动作虽都在 V1 范围内，但**实现必须串行推进**，且**每个动作独立验收**——达到可日用状态即算该动作完成，全部通过后 V1 才算交付：

```text
Ingest（含自动分区） → 浏览与图谱 → Query → Lint
```

理由：四个动作同时开工，结果是四个半成品；串行 + 独立验收能保证任意时刻都有可用的中间产物。

### 暂不做（明确排除）

| 排除项 | 原因 |
|---|---|
| 向量数据库 / 混合检索 | 与本模式核心主张冲突；当前规模不需要 |
| 代码仓库作为素材源 | 延后至 V2，仓库解析是独立工作量 |
| 抖音 / B站等视频链接 | 排除。依赖外部平台转写且合规边界不清 |
| 多人协作、账号鉴权、云端部署 | V1 只服务本人单机 |
| 移动端 / 响应式适配 | 超出单人维护能力 |
| 浏览器扩展（Web Clipper 同类） | 先用「粘贴 URL / 导入 md」替代 |
| 独立的定时调度基础设施（cron 式调度器） | 不需要：体检改为「启动 + 闲置」轻量自动触发即可达成 UX 目标 |
| ~~定时自动 lint 调度~~ | **已于 2026-09-15 修订**：轻量自动体检改列「必做」，仅此项剔除 |
| 导出 PDF / PPT / 幻灯片 | 非核心，排在 V2 |
| Obsidian 插件 | 采用「同一个文件夹」兼容策略即可 |
| 自动回滚 UI | 依托 git 命令行，不做界面按钮 |

## 8. 约束与风险

| 类型 | 内容 | 应对 |
|---|---|---|
| 约束 | 单人开发与维护，时间与精力有限 | 串行实现 + 逐动作验收，保证任意时刻有可用产物 |
| 约束 | 依赖云端 LLM，编译长文并级联更新 10~15 页成本可观 | 提供成本看板；长文分段处理 |
| 约束 | API key 需本机安全存储 | 不进版本库，走本地配置文件 |
| 风险 | **V1 四个动作全交付的排期风险**（用户已确认接受） | 串行实现 + 每动作独立验收，避免四个半成品 |
| 风险 | **LLM 自动分区误判** | 三项必要条件缺一不可：人工可改（`human_edited`）、操作留痕（MOD-08）、可回滚（git）。**若任一条件缺失，自动分区不得启用** |
| 风险 | **主题发散**：「全领域」缺少收敛目标 | 依赖增量式自动分区形成边界；由 lint 定期报告成员混杂、主题边界不清的分区 |
| 风险 | **幻觉污染**：编造事实沿互链扩散污染整张网 | 所有页面标注来源 `source_type`；矛盾由 MOD-06 标记；原料与结论可对照 |
| 风险 | 文件优先方案带来并发写、文件监听与原子写入复杂度 | 单写入进程；写入前读最新版；写操作串行化 |
