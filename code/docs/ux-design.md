## 1. UX 设计目标

| 编号 | 目标 |
|---|---|
| UX-001 | **提问优先**：产品第一屏就是提问框，知识库存在的意义是"能被问出东西"，不是"能被整理" |
| UX-002 | **冷启动可自举**：空库时不会被卡住，界面自己带你走完第一次填充 |
| UX-003 | **过程可见**：LLM 干活时用户看得懂它在干什么，不留黑箱感 |
| UX-004 | **结果可核对**：任何回答、任何页面都能顺着链接回到来源与改动记录 |
| UX-005 | **维护不打扰**：体检、分区整理、矛盾检查都在后台与次要入口，不打断主节奏 |
| UX-006 | **素材可控**：素材不是一次性消耗品，用户随时可以改它、删它、让它重新编译 |

## 2. 用户角色和使用场景

| 编号 | 角色 / 场景 |
|---|---|
| USER-001 | 唯一用户：个人开发者，本机使用，既是使用者也是维护者 |
| USER-002 | 场景 A · 沉淀：读到一篇好文章或拿到一份 PDF，想让它进库并自动长出页面 |
| USER-003 | 场景 B · 提问：有个需要综合多篇资料才能回答的问题，想要一个原料里没有的答案 |
| USER-004 | 场景 C · 探索：想看看某条知识周围连着什么，从一个页面漫游到另一个页面 |
| USER-005 | 场景 D · 维护：定期处理体检报出来的矛盾与孤儿页 |
| USER-006 | 场景 E · 纠错：发现某份素材本身有问题（标题错了、笔记要补几句、这篇不该留），需要改它或删它 |

## 3. 用户主流程

### FLOW-001 冷启动（第一次使用）

| 步骤 | 编号 | 用户做什么 | 界面给什么 |
|---|---|---|---|
| 1 | FLOW-001-01 | 打开应用 | 检测到 wiki 为空，首页自动落到素材投放页，并说明"还没有内容，先喂几篇" |
| 2 | FLOW-001-02 | 丢进 3~5 份素材 | 上传 / 粘贴 URL / 手写，三种方式任选 |
| 3 | FLOW-001-03 | 点「开始摄入」 | 进入编译围观页 |
| 4 | FLOW-001-04 | 看着它跑 | 实时显示正在读哪份素材、正在写哪个页面、已完成几个 |
| 5 | FLOW-001-05 | 编译完成 | 落到变更清单页 |
| 6 | FLOW-001-06 | 核对结果 | 看变更清单 / 直接跳到新写的页面 / 看它分到哪个区（不对可改） |
| 7 | FLOW-001-07 | 回到首页提问 | 此刻首页恢复为问答台，冷启动结束 |

### FLOW-002 日常摄入

| 步骤 | 编号 | 用户做什么 | 界面给什么 |
|---|---|---|---|
| 1 | FLOW-002-01 | 顶部导航点「喂素材」 | 进入素材投放页 |
| 2 | FLOW-002-02 | 投放素材 | 上传 / 粘贴 URL / 手写 |
| 3 | FLOW-002-03 | 点「开始摄入」 | 进入编译围观页 |
| 4 | FLOW-002-04 | 可留在围观，也可去做别的 | 后台继续跑，完成后给出通知 |
| 5 | FLOW-002-05 | 看结果 | 变更清单页：变更 + 新内容 + 分区 |
| 6 | FLOW-002-06 | 处理完毕 | 继续浏览，或回到首页提问 |

### FLOW-003 提问与回填

| 步骤 | 编号 | 用户做什么 | 界面给什么 |
|---|---|---|---|
| 1 | FLOW-003-01 | 在首页问答框输入问题 | 提交按钮，输入为空时禁用 |
| 2 | FLOW-003-02 | 提交 | 显示"正在综合 N 个页面…"的进度提示 |
| 3 | FLOW-003-03 | 阅读答案 | 跨页综合的答案 + 内联 `[[引用]]`，点一下跳到那个页面 |
| 4 | FLOW-003-04 | （可选）觉得答案有价值 | 点答案卡片上的次要按钮「存为页面」，该答案变成 wiki 页面（标注为答案产物） |
| 5 | FLOW-003-05 | （可选）回看 | 从问答历史进入，重放上次问答 |
| 6 | FLOW-003-06 | 顺着引用深入 | 跳到页面详情继续探索（转 FLOW-004） |

### FLOW-004 探索与溯源

| 步骤 | 编号 | 用户做什么 | 界面给什么 |
|---|---|---|---|
| 1 | FLOW-004-01 | 通过搜索 / 分区浏览 / 图谱点选找到页面 | 三种寻路方式都可用 |
| 2 | FLOW-004-02 | 进入页面详情 | 正文 + 右侧反向链接面板 + 底部来源区 |
| 3 | FLOW-004-03 | 点反向链接或内联链接 | 跳到相邻页面，形成漫游 |
| 4 | FLOW-004-04 | 点来源区 | 打开素材原文页，看到原始出处 |
| 5 | FLOW-004-05 | （可选）纠偏 | 发现分区不对可一键改区；发现写得不对可直接编辑（打人工编辑标记） |

### FLOW-005 体检与修复

| 步骤 | 编号 | 用户做什么 | 界面给什么 |
|---|---|---|---|
| 1 | FLOW-005-01 | 应用启动或闲置时自动体检 | 导航栏常驻「N 个待处理」 |
| 2 | FLOW-005-02 | 点提醒进入体检报告页 | 按类型分组列出：矛盾 / 孤儿页 / 失效链接 / 缺失索引 / 分区混杂 |
| 3 | FLOW-005-03 | 勾选想处理的条目 | 每条给出建议动作 |
| 4 | FLOW-005-04 | 执行修复 | 后台重跑相关页面，同样产出变更清单 |
| 5 | FLOW-005-05 | 完成 | 待处理数下降，条目归档 |

### FLOW-006 素材编辑与删除

| 步骤 | 编号 | 用户做什么 | 界面给什么 |
|---|---|---|---|
| 1 | FLOW-006-01 | 从素材库或原文页点「编辑」 | 进入编辑态：手写笔记可改正文，网页/PDF 可改标题、标签、备注 |
| 2 | FLOW-006-02 | 保存 | 提示"已保存，需重编译才会同步到 wiki"（CONTENT-007） |
| 3 | FLOW-006-03 | 点「重编译」 | 走与首次摄入相同的围观 → 变更清单流程 |
| 4 | FLOW-006-04 | （可选）点「删除」 | 二次确认后软删除 |
| 5 | FLOW-006-05 | 删除后 | 素材标记为已删除，其派生页面与入链标为失效，由体检列出（可恢复） |
| 6 | FLOW-006-06 | 误删恢复 | 从已删除筛选中找到并恢复，重新可用 |

## 4. 分支流程

| 编号 | 分支 | 触发条件 | 走向 |
|---|---|---|---|
| BRANCH-001 | 空库自动导向 | wiki 页面数为 0 | 首页直接渲染素材投放页，并给出一句引导文案 |
| BRANCH-002 | 围观中离开 | 用户在编译进行中切走 | 编译继续，顶部出现进度胶囊，完成后通知；随时可回围观页 |
| BRANCH-003 | 答案回填 | 用户在答案卡片点「存为页面」 | 生成新 wiki 页，`source_type` 标为答案产物，可在变更清单中看到 |
| BRANCH-004 | 分区纠正 | 变更清单或页面详情发现分错区 | 一键改分区；改动记入变更记录，可由 git 回退 |
| BRANCH-005 | 体检结果保留 | 用户不处理某条待处理项 | 条目保留在报告页，不被自动清除（除非用户显式忽略） |
| BRANCH-006 | 编辑素材后的同步 | 用户修改素材并保存 | 素材进入「待重编译」状态，**不自动编译**，由用户显式触发 |
| BRANCH-007 | 删除素材的后续 | 用户软删除素材 | 派生页面与入链标记为失效并入体检报告；用户可随时恢复 |

## 5. 异常、中断和返回路径

| 编号 | 异常 | 界面行为 | 用户可做什么 |
|---|---|---|---|
| ERROR-001 | LLM 调用失败 / 超时 | 已写入的页面保留，该素材标记为失败并说明原因 | 重试 / 跳过 / 查看已产出的部分 |
| ERROR-002 | 素材解析失败（如 PDF 损坏） | 该素材标记失败，原文件保留 | 手动另行处理或移除 |
| ERROR-003 | 素材重复导入 | 提示"已存在同名/同源素材" | 选择"重新编译"或"取消" |
| ERROR-004 | 全局搜索无结果 | 显示空态 + 建议关键词/入口 | 转入投放或浏览 |
| ERROR-005 | 问答时知识不足 | 明确回答"现有页面不足以回答这个问题"，并列出相关度最高的页面 | 决定是否补充素材后再问 |
| ERROR-006 | 点击了失效/已删除页面链接 | 显示失效提示页，说明去向 | 从失效处跳到相邻页面或体检报告 |
| ERROR-007 | 编译中断（关闭标签页 / 断网 / 重启） | 恢复后继续未完成的部分，不从头重来 | 查看进度并续跑 |
| ERROR-008 | API key 无效 / 余额不足 | 明确报错并指向设置页 | 更换 key 后继续 |
| ERROR-009 | 编辑正在编译中的素材 | 编辑入口置灰并说明原因 | 等编译结束后再编辑 |
| ERROR-010 | 删除素材时它仍被页面引用 | 明确告知受影响页面数量，要求二次确认 | 确认删除 / 取消 |

**返回路径原则**：任何深层页面（页面详情、原文、变更项、体检条目、素材编辑）都保留「回到上一处」的能力；素材删除采用软删除，可恢复。

## 6. 页面职责

| 编号 | 页面 | 职责 | 不做什么 |
|---|---|---|---|
| PAGE-001 | 首页 · 问答台 | V1 主入口。提问输入、答案展示与内联引用跳转、答案回填次要入口、问答历史入口 | 不负责素材管理、不展示全量通知 |
| PAGE-002 | 素材投放页 | 三种入口集中地：上传文件 / 粘贴 URL / 手写笔记；空库时作为临时候补首页 | 不做历史素材管理 |
| PAGE-003 | 编译围观页 | 实时展示正在读哪份素材、正在写哪个页面、完成进度、是否报错、累计花费；支持离开后继续 | 不提供中断编辑能力，不改任何知识内容 |
| PAGE-004 | 变更清单页 | 编译/修复完成后第一眼：① 本次改了哪些页面（可展开 diff）② 新生成的页面入口 ③ 自动分区结果与一键改区 | 不做全量历史 diff 检索 |
| PAGE-005 | 页面详情页 | wiki 页面正文渲染、内联链接跳转、反向链接面板、来源区、分区显示、人工编辑入口 | 不自动生成内容 |
| PAGE-006 | 全局图谱页 | 呈现整张知识网络，支持按分区筛选与 1/2 层深度切换，点节点跳到对应页面 | 不提供编辑 |
| PAGE-007 | 分区浏览页 | 分区列表 → 该分区下的页面列表 | 不承载搜索结果；不提供分区体系的增删改名（跟随自动聚类） |
| PAGE-008 | 搜索结果页 | 展示全局搜索命中的页面，点击进入详情 | V1 不做高级筛选 |
| PAGE-009 | 问答历史页 | 历史问答列表与回放，支持删除单条 | 不做分享/导出/批量清理 |
| PAGE-010 | 素材原文页 | 展示原始素材内容与元信息、它由哪些 wiki 页面派生；**提供编辑入口（受限）与删除入口** | 网页/PDF 的正文不可改（外部来源），仅改元数据 |
| PAGE-011 | 体检报告页 | 按类型分组列出矛盾、孤儿页、失效链接、缺失索引、分区混杂；支持勾选修复与显式忽略（需写原因） | 不自动修复 |
| PAGE-012 | 设置页 | 模型 provider / 模型名 / API key / 成本看板 / 打开数据文件夹入口 | 不做多用户配置 |
| PAGE-013 | 素材库页 | 所有素材总览：按状态筛选（正常 / 失败 / 已删除 / 待重编译）、**编辑**、软删除与恢复、重编译、查看原文 | 不改外部来源素材的正文内容 |

## 7. 页面关系

```text
                      ┌─ 空库 ──→ PAGE-002 素材投放 ─┐
打开应用 ─→ PAGE-001 ─┤                              ├─→ PAGE-003 编译围观 ─→ PAGE-004 变更清单
    ↑↑ 问答台         └─ 常态 ──→ 导航「喂素材」─────┘                │
    │                                                          └─→ PAGE-005 页面详情 ←─────┐
    ├─→ PAGE-013 素材库 ─→ 编辑 / 软删除 / 恢复 / 重编译 ─→ PAGE-003
    │              └─→ 查看原文（PAGE-010 编辑与删除在此也可用）          │                   │
    ├─→ PAGE-009 问答历史                                              ├─→ PAGE-010 素材原文 │
    │                                                                  ├─→ 反向链接 →───────┘
    │   寻路三入口：PAGE-006 图谱 / PAGE-007 分区 / PAGE-008 搜索 ──────┘
    │
    └── 导航栏「N 个待处理」─→ PAGE-011 体检报告 ─→ 修复 ─→ PAGE-004 变更清单
                              导航栏设置入口 ─→ PAGE-012 设置页 ─→ 打开数据文件夹（系统文件管理器）
```

**跳转优先级原则**：答案里的引用、正文里的内联链接、反向链接面板三者**都跳同一个 PAGE-005**，不存在第二种页面详情。

## 9. 页面状态

通用状态适用于所有页面；特化状态单独列出。

| 编号 | 状态 | 适用范围 | 界面表现 |
|---|---|---|---|
| STATE-001 | 默认 | 全部 | 正常内容渲染 |
| STATE-002 | 加载中 | 全部 | 骨架屏 / 局部加载指示，不阻塞其他操作 |
| STATE-003 | 空 | 全部 | 空态插画 + 一句引导 + 首要行动按钮 |
| STATE-004 | 成功 | 操作类 | 短暂成功提示，不强制打断 |
| STATE-005 | 错误 | 全部 | 明确错误文案 + 可执行的下一步（重试/去设置/返回） |
| STATE-006 | 空库临时候补 | PAGE-001 | 不渲染问答框，整页替换为 PAGE-002 内容 + 引导文案 |
| STATE-007 | 编译进行中 | PAGE-003 | 实时步骤列表 + 进度 + 累计花费 + 可离开标志 |
| STATE-008 | 无待处理项 | PAGE-011 | 显示"当前没有需要处理的问题" |
| STATE-009 | 人工编辑标记 | PAGE-005 | 页面顶部标注"已被人工编辑"，并提示体检不会自动覆盖 |
| STATE-010 | 素材失败 | PAGE-002 / 010 / 013 | 标红 + 原因 + 重试/移除操作 |
| STATE-011 | 知识不足 | PAGE-001 答案区 | 明确说"现有页面不足以回答"，列出最相关页面 |
| STATE-012 | 已软删除 | PAGE-013 | 素材标记为已删除，其派生页面与入链显示为失效，可恢复 |
| STATE-013 | 待重编译 | PAGE-013 / 010 | 素材已被修改但未同步，显示"内容已更新，重编译后生效" |

## 10. 用户反馈

| 编号 | 反馈场景 | 文案要点（面向 UI 阶段） |
|---|---|---|
| CONTENT-001 | 空库引导 | "还没有内容，先喂 3~5 篇素材，问答才有东西可问" |
| CONTENT-002 | 提交问题的等待 | "正在综合 N 个页面…"，不要只转圈 |
| CONTENT-003 | 知识不足 | 直说答不上来，并给出最相关页面，不编造答案 |
| CONTENT-004 | 编译失败 | 说清哪一步失败 + 已保留了什么 + 可重试/跳过 |
| CONTENT-005 | 分区结果 | 明示"自动归入 XX 区"，并提供"改到别的区"入口 |
| CONTENT-006 | 体检提醒 | 导航栏 N 个待处理，不用形容词，用数量 |

## 11. UX 验收标准

| 编号 | 验收项 | 对应需求 |
|---|---|---|
| UX-AC-001 | 新用户从打开应用到完成第一次编译并回到首页提问，全程不超过 4 次点击进入下一步 | SC-2、FLOW-001 |

## 13. 人工确认结论

**用户已确认的 UX 决策：**

- 首页形态：问答框优先
- 空库处理：首页临时变成摄入页（BRANCH-001）
- 素材入口：上传 / 新建手写 / 粘贴 URL 三种，**未采纳** `raw/` 目录监听自动触发
- 编译模式：围观（可见进度），不作人工把关
- 编译完成首看内容：新生成的内容本身、本次改了哪些页面、它被分到哪个区；**未选择**「发现的矛盾与缺口」（矛盾统一移交体检）
- 答案呈现：综合答案 + 内联引用、保留历史；**未选择**侧栏参与页面
- 回填能力：保留，放次要入口
- 编译中断：保留已写入内容，标记失败可重试
- 导航方式：反向链接面板 + 独立图谱页
- 溯源方式：wiki 页内置来源区
- 寻路方式：全局搜索 + 分区浏览 + 图谱点选（**未选择**索引页）
- 体检方式：自动触发 + 常驻提醒（已触发需求修订 UI-冲突-01）
- 素材管理：增设 PAGE-013 素材库页
- **素材允许编辑与删除**（本轮新增，已触发需求文档第二次修订）
- UX-TBD-001~010 全部处理：确认 8 项、延后 1 项（005）、排除 1 项（010），009 拆分处理
