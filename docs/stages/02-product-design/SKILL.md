# Product Design Skill（阶段 2A + 2B）

## 目标

本 Skill 负责阶段 2 的两步，严格有先后关系：

阶段 2A：交互式生成 UX 文档

```text
读取 requirement-analysis.md
→ AI 总结需求
→ AI 分轮询问用户
→ 梳理用户流程和页面职责
→ 补充交互、状态和异常路径
→ AI 自查完整性和一致性
→ 用户逐项确认
→ 生成 ux-design.md
```

阶段 2B：生成 UI 文档和设计图

```text
读取已确认的 ux-design.md
→ 提取页面清单、页面状态和交互
→ 建立全局设计系统（色彩 / 字体 / 间距 / 组件 / 可访问性）
→ 用户确认设计系统
→ 直接输出设计图（默认），或输出设计图提示词
→ 回填设计图路径（或提示词）、尺寸和版本
→ 生成 ui-design.md
```

阶段 2B 必须在阶段 2A 完成且用户确认 `ux-design.md` 之后才能开始。

阶段 2B 不要求用户把提示词粘贴到外部设计工具。AI 应默认直接产出设计图；只有在用户明确只要提示词、或本地确实无法渲染出图时，才以提示词作为交付形式。

## 固定文件

阶段 1 输入：

```text
code/docs/requirement-analysis.md
```

阶段 2A 输出：

```text
code/docs/ux-design.md
```

阶段 2B 输入：

```text
code/docs/ux-design.md
```

阶段 2B 输出：

```text
code/docs/ui-design.md
```

文件名固定，不得改名，否则下一阶段无法读取。

如果阶段 1 输入文件不存在，或仍有未处理的未确定事项，不能开始本 Skill。

# 阶段 2A：UX 文档

UX 阶段只处理：

- 用户目标
- 用户角色和使用场景
- 用户主流程
- 分支、异常、中断和返回路径
- 页面职责
- 页面之间的关系
- 关键交互
- 页面状态
- 用户反馈

UX 阶段不处理：

- 色彩
- 字体
- 图标
- 阴影
- 视觉风格
- 组件美化
- UI 设计图
- 技术实现

## 交互式工作流程

### 第 1 步：读取阶段 1 需求

AI 必须先读取：

```text
code/docs/requirement-analysis.md
```

提取并总结：

- 目标用户
- 用户问题
- 需求目标
- 成功标准
- 必须支持的范围
- 模块边界
- 已确认的限制和风险

不要要求用户重新填写项目名称、产品背景或模板。

### 第 2 步：总结当前理解

AI 先用简短内容说明：

- 当前理解的用户
- 当前理解的核心任务
- 可能涉及的主要模块
- 当前还不清楚的 UX 问题

等待用户确认方向后再继续提问。

### 第 3 步：分轮询问 UX 问题

AI 每轮只问少量最关键的问题，不要一次性生成完整 UX，也不要一次抛出大量问题。

推荐询问顺序：

1. 用户最重要的任务是什么？
2. 用户从哪里开始？
3. 用户需要经过哪些步骤？
4. 每一步需要看到什么、做什么？
5. 操作成功后如何反馈？
6. 空数据、错误、中断和返回时如何继续？
7. 多个模块之间如何跳转和关联？

用户回答后，AI 必须：

1. 更新当前理解；
2. 指出仍然不清楚的点；
3. 再提出下一组少量问题。

### 第 4 步：生成 UX 草稿

信息足够后，AI 生成 UX 草稿，至少包含：

- UX 设计目标
- 用户角色和使用场景
- 用户主流程
- 分支流程
- 异常、中断和返回路径
- 页面职责
- 页面之间的关系
- 关键交互
- 页面状态
- 用户反馈
- UX 待确认事项

### 第 5 步：自查 UX 完整性和一致性

用户初步确认草稿后，AI 必须主动检查，不要等用户发现问题。

至少检查：

1. 页面职责是否重叠；
2. 模块边界是否清楚；
3. 是否存在定义空泛、无法执行的页面或模块；
4. 主流程是否完整可走通；
5. 是否遗漏分支、异常、返回和恢复路径；
6. 是否覆盖默认、加载、空、成功和错误状态；
7. 每个核心需求是否都有对应页面或流程；
8. 页面入口、出口和跳转是否明确；
9. 交互是否有成功和失败反馈；
10. 是否出现未经确认的新功能；
11. 是否存在 UX 术语或编号不一致。

AI 必须将发现的问题分为：

- **必须澄清**：会影响流程、页面结构或用户目标；
- **建议补充**：不会阻塞流程，但影响完整性。

然后逐条向用户询问并更新草稿。

### 第 6 步：处理 UX 待确认事项

所有 UX 待确认事项必须逐项询问用户，处理方式为：

- 确认
- 排除
- 延后
- 继续追问

如果处理某一事项时产生新的待确认点，必须加入列表并继续处理，直到没有未处理事项。

### 第 7 步：用户最终确认

AI 应向用户展示最终 UX 草稿，并明确询问：

- 用户流程是否准确；
- 页面职责是否合理；
- 交互和状态是否完整；
- 自查发现的问题是否已经处理；
- 是否确认生成最终 UX 文档。

用户未确认时，不得保存最终文件。

### 第 8 步：生成 UX 文档

用户确认后，生成：

```text
code/docs/ux-design.md
```

这个文件是阶段 2B 生成 UI 文档和设计图的唯一 UX 输入。

## UX 文档结构

最终 `ux-design.md` 至少包含：

1. UX 设计目标
2. 用户角色和使用场景
3. 用户主流程
4. 分支流程
5. 异常、中断和返回路径
6. 页面职责
7. 页面关系
8. 关键交互
9. 页面状态
10. 用户反馈
11. UX 验收标准
12. 待确认事项处理结果
13. 人工确认结论

## UX 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UX 设计任务 | `UX-###` | `UX-001` |
| 用户角色 | `USER-###` | `USER-001` |
| 用户流程步骤 | `FLOW-###-##` | `FLOW-001-01` |
| 分支流程 | `BRANCH-###` | `BRANCH-001` |
| 异常情况 | `ERROR-###` | `ERROR-001` |
| 页面 | `PAGE-###` | `PAGE-001` |
| 交互 | `INTERACTION-###` | `INTERACTION-001` |
| 页面状态 | `STATE-###` | `STATE-001` |
| 内容提示 | `CONTENT-###` | `CONTENT-001` |
| 待确认事项 | `UX-TBD-###` | `UX-TBD-001` |

同一编号必须在 UX 文档和后续 UI 文档中保持一致。

## 可直接复制的启动提示词

```text
我现在开始阶段 2A：生成 UX 文档。

请先读取：
code/docs/requirement-analysis.md

我不填写 UX 模板，请通过交互式对话引导我完成：
1. 先总结需求中的用户、目标和核心任务；
2. 每轮只问少量最关键的 UX 问题；
3. 根据我的回答逐步梳理用户流程、页面职责和页面状态；
4. 生成 UX 草稿让我确认；
5. 主动检查模块重叠、流程遗漏、状态遗漏和逻辑矛盾；
6. 将自查发现的问题逐条向我确认；
7. 逐项处理所有待确认事项，包括过程中新增的事项；
8. 我最终确认后，生成：
code/docs/ux-design.md

不要进入 UI 设计，不要生成颜色、字体或视觉效果图。
```

## 完成条件

- [ ] 已读取 `requirement-analysis.md`
- [ ] 已通过多轮交互确认用户目标和流程
- [ ] 主流程、分支、异常和中断路径已明确
- [ ] 页面职责和页面关系已明确
- [ ] 关键交互和反馈已明确
- [ ] 页面状态已覆盖
- [ ] 已完成 UX 重叠、遗漏和矛盾自查
- [ ] 自查问题已逐项处理
- [ ] 所有待确认事项已处理
- [ ] 用户已确认最终 UX 草稿
- [ ] 已生成 `ux-design.md`

## 不要做的事

- 不要要求用户填写 UX 模板
- 不要跳过读取阶段 1 需求
- 不要一次性抛出大量问题
- 不要未经确认编造用户流程
- 不要在 UX 阶段决定颜色、字体或视觉风格
- 不要跳过自查
- 不要把重叠、遗漏和矛盾留给用户发现
- 不要在用户确认前生成最终 `ux-design.md`
- 不要在 UX 未确认时进入 UI 设计

# 阶段 2B：UI 文档和设计图

## UI 的职责

UI 阶段只处理：

- 视觉风格和氛围
- 色彩、字体、间距、圆角、阴影
- 组件视觉规范
- 页面视觉布局
- 图标风格
- 可访问性要求（对比度、触控目标、聚焦状态）
- 设计图的直接输出方式与设计图提示词

UI 阶段不处理：

- 修改用户流程
- 修改页面职责
- 修改交互逻辑
- 新增未经确认的页面或功能

如果发现 UX 问题，必须先回到阶段 2A 修改 `ux-design.md`，不要在 UI 阶段静默地改掉。

## 交互式工作流程

### 第 1 步：读取已确认的 UX 文档

AI 必须先读取：

```text
code/docs/ux-design.md
```

提取并核对：

- 页面清单（`PAGE-###`）
- 页面状态（`STATE-###`）
- 关键交互（`INTERACTION-###`）
- 内容文案（`CONTENT-###`）

如果 `ux-design.md` 仍有未处理的待确认事项，不能开始阶段 2B。

### 第 2 步：确认设计方向

AI 先用少量问题确认视觉方向，至少覆盖：

1. 视觉风格和氛围（例如温暖友好、专业冷静、简约中性）；
2. 主色倾向和是否需要深色主题；
3. 品牌约束或已有设计系统；
4. 目标平台和设计基准（例如 375 × 812 pt）；
5. 是否有必须遵守的行业或无障碍规范。

每轮只问少量问题，不要一次性问完。

### 第 3 步：建立全局设计系统

AI 先定义一套全局设计系统，再写页面提示词。至少包含：

- 设计标准和可访问性基线（对比度、触控目标、聚焦状态）
- 布局规范（基准尺寸、边距、间距体系、栅格）
- 色彩规范（主色、背景、文字、分割线、成功 / 警告 / 错误）
- 字体规范（字号、字重、行高）
- 组件规范（按钮、输入框、卡片、胶囊、分段控件、空状态）

设计系统必须先给用户确认，再批量生成页面提示词。

### 第 4 步：生成页面提示词

AI 为每个 `PAGE-###` 生成一段可直接使用的提示词，至少包含：

- 页面目标
- 从上到下的布局结构
- 关键内容元素和文案
- 需要生成的状态

要求：

- 提示词必须使用 `ux-design.md` 中已确认的页面职责、交互和文案；
- 不得新增页面、功能或流程；
- 不得把两个页面合并成一个提示词。

### 第 5 步：生成一次性完整提示词

除单页提示词外，AI 还要输出一段**完整提示词**，把设计系统、全部页面和全局状态合并成一个自包含的 `text` 代码块，使用户一次提交就能生成全部 UI 设计图。

完整提示词必须自包含，至少包含：

- 任务说明和页面总数
- 整体风格
- 设计基准与布局
- 色彩、字体、组件
- 可用性要求
- 逐页 `PAGE-###` 要点和状态
- 全局状态补充
- 输出要求（编号格式、不得遗漏和合并页面、交付物是设计图而不是生产代码）

单页提示词与完整提示词必须描述同一套设计，不得出现颜色、间距或文案不一致。

### 第 6 步：直接输出设计图（默认）或输出设计图提示词

阶段 2B 默认由 AI 直接产出设计图，不需要用户把提示词粘贴到外部设计工具。

输出方式：

1. **直接输出设计图（默认）**：AI 用本地可复现的方式渲染出图，例如生成 HTML/CSS 设计稿后用无头浏览器截图，把图片文件落到阶段 2 的产物目录，并在 `ui-design.md` 中记录文件路径与尺寸。
2. **输出设计图提示词**：当用户明确只要提示词，或本地不具备渲染条件时，AI 输出完整提示词与单页提示词，供用户自行选择工具出图。

规则：

- 采用直接出图时，必须同时保留可复现的渲染源码，并在文档中说明重新出图的方式；
- 采用提示词交付时，提示词必须自包含、可独立使用，不绑定任何特定设计工具；
- 无论采用哪种方式，设计图与提示词都必须与已确认的全局设计系统一致；
- 直接出图时，渲染产物必须能覆盖 `PAGE-###` 与 `STATE-###`，跳转型状态（如会话过期）可以不单独出图，但必须在文档中说明由哪个页面承载；
- 如果用户反馈设计图或提示词有问题，AI 应做针对性修改并更新对应产物，而不是重写全部内容。

### 第 7 步：回填设计图和版本

设计图产出后，AI 回填：

- 设计图文件路径（或用户自行出图时提供的链接）
- 图片尺寸
- 版本号
- 修改原因和是否采纳

每个设计图必须有 `UI-###` 编号，并对应具体的 `PAGE-###` 和 `STATE-###`。

### 第 8 步：处理 UI 待确认事项

所有 `UI-TBD-###` 必须逐项询问用户，处理方式为：

- 确认
- 排除
- 延后
- 继续追问

过程中产生的新事项同样加入列表，直到没有未处理事项。

### 第 9 步：生成 UI 文档

用户确认后，生成：

```text
code/docs/ui-design.md
```

## UI 文档结构

最终 `ui-design.md` 至少包含：

1. UI 设计范围
2. 设计图提示词（完整提示词 + 全局设计系统提示词）
3. 页面提示词（每个 `PAGE-###` 一段）
4. 状态提示词
5. 视觉设计规范（设计标准 / 布局 / 色彩 / 字体 / 组件）
6. 界面设计图（`UI-###` 编号、页面编号、状态、文件路径或链接、尺寸、版本）
7. UI 版本记录
8. UI 验收标准
9. 待确认的 UI 问题

## UI 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UI 设计任务 | `UI-###` | `UI-001` |
| 颜色 | `COLOR-###` | `COLOR-001` |
| 字体样式 | `TYPE-###` | `TYPE-001` |
| 组件 | `COMPONENT-###` | `COMPONENT-001` |
| 待确认事项 | `UI-TBD-###` | `UI-TBD-001` |

UI 文档必须复用 UX 文档中的 `PAGE-###`、`STATE-###` 和 `INTERACTION-###` 编号，不得重新编号。

## 可直接复制的启动提示词

```text
我现在开始阶段 2B：生成 UI 文档和设计图。

请先读取：
code/docs/ux-design.md

我不填写 UI 模板，请通过交互式对话引导我完成：
1. 先总结页面清单、页面状态和关键交互；

3. 先给出全局设计系统（布局、色彩、字体、组件、可访问性）让我确认；

5. 再生成一段完整提示词，能覆盖全部页面；

7. 逐项处理所有 UI 待确认事项；
8. 我最终确认后，生成：
code/docs/ui-design.md

不要修改 ux-design.md 中已确认的用户流程、页面职责和交互逻辑。
```

- [ ] 每个 `PAGE-###` 都有单页提示词
- [ ] 已生成可覆盖全部页面的完整提示词

- [ ] 已按选定方式直接输出设计图，或输出设计图提示词
- [ ] 设计图路径（或提示词）、`UI-###` 编号、`PAGE-###` 映射、尺寸和版本已回填
- [ ] 所有 `UI-TBD-###` 已处理
- [ ] UI 设计未改动已确认的 UX 流程和页面职责

- [ ] 已生成 `ui-design.md`

## 不要做的事

- 不要要求用户填写 UI 模板
- 不要跳过读取已确认的 `ux-design.md`
