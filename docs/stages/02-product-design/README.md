# 阶段 2：产品设计

## 阶段目标

阶段 2 分为两个严格有先后关系的步骤：

```text
阶段 2A：生成 UX 文档
读取阶段 1 需求分析文档
→ AI 通过 Skill 与用户交互式询问
→ 梳理用户流程、页面职责和页面状态
→ 用户确认
→ 生成 ux-design.md

阶段 2B：生成 UI 文档和设计图
读取已确认的 ux-design.md
→ 确认视觉方向和全局设计系统
→ 生成单页提示词和一次性完整提示词
→ 直接输出设计图（默认），或输出设计图提示词
→ 回填设计图路径、尺寸和版本
→ 生成 ui-design.md
```

两个步骤严格有先后关系，阶段 2B 必须在 `ux-design.md` 确认后才能开始。

阶段 2B 不需要你把提示词粘贴到外部设计工具。默认由 AI 直接产出设计图；只有你明确只要提示词，或本地无法渲染出图时，才以提示词作为交付形式。

## 固定文件

阶段 1 输入：

```text
code/docs/requirement-analysis.md
```

阶段 2 Skill：

```text
docs/stages/02-product-design/SKILL.md
```

阶段 2A 输出：

```text
code/docs/ux-design.md
```

阶段 2B 输入和输出：

```text
code/docs/ux-design.md
code/docs/ui-design.md
```

当前不需要用户填写任何模板。`ux-design.md` 和 `ui-design.md` 均由 AI 按 Skill 通过交互式问答生成。

如果 `requirement-analysis.md` 不存在，或阶段 1 仍有未处理的未确定事项，应先回到阶段 1。

# 阶段 2A：生成 UX 文档

## 目标

把阶段 1 的需求转化为清晰的用户体验和交互逻辑，形成可以被用户确认、并可供阶段 2B 生成 UI 的 UX 文档。

UX 阶段关注：

- 用户目标
- 用户角色和使用场景
- 用户流程
- 页面职责
- 页面之间的关系
- 关键交互
- 分支、异常、中断和返回路径
- 页面状态
- 用户反馈

UX 阶段不关注：

- 颜色
- 字体
- 图标
- 阴影
- 视觉风格
- 组件美化
- UI 设计图

## UX 交互流程

### 第 1 步：读取阶段 1 文档

AI 必须先读取：

```text
code/docs/requirement-analysis.md
```

先总结与用户体验有关的内容：

- 目标用户
- 用户问题
- 需求目标
- 成功标准
- 必须支持的范围
- 模块边界和限制

不要求用户重新填写项目名称、产品背景或技术信息。

### 第 2 步：分轮询问用户

AI 不应直接编造完整 UX 文档，而应通过多轮对话逐步确认：

1. 用户最重要的任务是什么？
2. 用户从哪里开始？
3. 用户需要经过哪些步骤？
4. 每一步需要看到什么、做什么？
5. 用户操作成功后如何反馈？
6. 用户遇到空数据、错误或中断时如何继续？
7. 多个模块之间如何跳转和关联？

每轮只询问少量最关键的问题。用户回答后，AI 更新当前理解，再继续询问下一组问题。

### 第 3 步：生成 UX 草稿

信息足够后，AI 生成 UX 草稿，至少包含：

- UX 设计目标
- 用户角色和使用场景
- 用户主流程
- 分支流程
- 异常、中断和返回路径
- 页面职责
- 页面之间的关系
- 关键交互
- 页面状态
- 用户反馈
- UX 待确认事项

### 第 4 步：自查 UX 完整性

用户初步确认草稿后，AI 必须主动检查：

- 页面职责是否重叠
- 模块边界是否清楚
- 主流程是否能完整走通
- 是否遗漏分支、异常、返回和恢复路径
- 页面状态是否覆盖默认、加载、空、成功和错误
- 交互是否有明确的成功和失败反馈
- 需求中的每个核心功能是否有对应页面或流程
- 是否出现未经确认的新功能

发现问题后，AI 必须分为“必须澄清”和“建议补充”，再逐条询问用户。

### 第 5 步：逐项处理 UX 待确认事项

UX 草稿中的待确认事项不能只列出后直接结束。每一项必须处理为：

- 确认
- 排除
- 延后
- 继续追问

如果处理过程中产生新的待确认事项，也要加入列表继续处理，直到所有事项都有明确结果。

### 第 6 步：生成最终 UX 文档

只有用户确认以下内容后，才能生成：

```text
code/docs/ux-design.md
```

最终 UX 文档必须保留编号、流程、页面、状态、交互和验收标准，作为阶段 2B 的唯一 UX 输入。

## UX 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UX 设计任务 | `UX-###` | `UX-001` |
| 用户角色 | `USER-###` | `USER-001` |
| 用户流程步骤 | `FLOW-###-##` | `FLOW-001-01` |
| 分支流程 | `BRANCH-###` | `BRANCH-001` |
| 异常情况 | `ERROR-###` | `ERROR-001` |
| 页面 | `PAGE-###` | `PAGE-001` |
| 交互 | `INTERACTION-###` | `INTERACTION-001` |
| 页面状态 | `STATE-###` | `STATE-001` |
| 内容提示 | `CONTENT-###` | `CONTENT-001` |
| 待确认事项 | `UX-TBD-###` | `UX-TBD-001` |

同一编号必须在 UX 文档和后续 UI 文档中保持一致。

# 阶段 2B：UI 文档和设计图

## 目标

把已确认的 UX 文档转化为 UI 设计规范、设计图提示词和设计图，形成可供后续阶段引用的 UI 文档。

UI 阶段关注：

- 视觉风格和氛围
- 色彩、字体、间距、圆角、阴影
- 组件视觉规范
- 页面视觉布局
- 图标风格
- 可访问性（对比度、触控目标、聚焦状态）
- 设计图提示词与设计图的直接输出

UI 阶段不关注：

- 用户流程
- 页面职责
- 交互逻辑
- 新增功能

## UI 交互流程

### 第 1 步：读取已确认的 UX 文档

AI 必须先读取：

```text
code/docs/ux-design.md
```

核对页面清单（`PAGE-###`）、页面状态（`STATE-###`）、关键交互（`INTERACTION-###`）和内容文案（`CONTENT-###`）。如果 `ux-design.md` 仍有未处理的待确认事项，不能开始阶段 2B。

### 第 2 步：确认设计方向并建立设计系统

先用少量问题确认视觉风格、主色倾向、是否需要深色主题、目标平台和设计基准，再定义全局设计系统：

- 设计标准和可访问性基线
- 布局规范
- 色彩规范
- 字体规范
- 组件规范

设计系统需经用户确认后，再批量生成页面提示词。

### 第 3 步：生成页面提示词

为每个 `PAGE-###` 生成一段可直接使用的提示词，包含页面目标、布局结构、内容元素和需要生成的状态。提示词不得新增页面、功能或流程。

### 第 4 步：生成一次性完整提示词

除单页提示词外，还要输出一段完整提示词，把设计系统、全部页面和全局状态合并成一个自包含的代码块，使用户一次提交就能生成全部 UI 设计图。

单页提示词与完整提示词必须描述同一套设计，不得出现颜色、间距或文案不一致。

### 第 5 步：直接输出设计图，或输出设计图提示词

默认由 AI 直接产出设计图，例如生成 HTML/CSS 设计稿后用无头浏览器截图，把图片落到阶段 2 的产物目录。只有在用户明确只要提示词，或本地无法渲染出图时，才改为输出设计图提示词。

直接出图时必须保留可复现的渲染源码，并说明重新出图的方式。跳转型状态（如会话过期）可以不单独出图，但要说明由哪个页面承载。

### 第 6 步：回填设计图和版本

AI 回填设计图文件路径（或用户自行出图时的链接）、图片尺寸、版本号和修改记录。

每个设计图必须有 `UI-###` 编号，并对应具体的 `PAGE-###` 和 `STATE-###`。

### 第 7 步：逐项处理 UI 待确认事项

所有 `UI-TBD-###` 必须处理为确认 / 排除 / 延后 / 继续追问，过程中新增的事项同样加入列表。

### 第 8 步：生成最终 UI 文档

用户确认后生成：

```text
code/docs/ui-design.md
```

## UI 编号规则

| 对象 | 编号格式 | 示例 |
|---|---|---|
| UI 设计任务 | `UI-###` | `UI-001` |
| 颜色 | `COLOR-###` | `COLOR-001` |
| 字体样式 | `TYPE-###` | `TYPE-001` |
| 组件 | `COMPONENT-###` | `COMPONENT-001` |
| 待确认事项 | `UI-TBD-###` | `UI-TBD-001` |

UI 文档必须复用 UX 文档中的 `PAGE-###`、`STATE-###` 和 `INTERACTION-###` 编号，不得重新编号。

## 约束

UI 设计不能修改已确认的 UX 用户流程、页面职责或交互逻辑。发现 UX 问题时，应先回到阶段 2A 修改 `ux-design.md`。
